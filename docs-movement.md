# docs-old → new IA movement plan

This document tracks how legacy `src/content/docs-old` content maps into the new IA under `src/content/docs`, and
identifies items to **delete**, **split**, or **rework**.

Status legend:

- **kept →** mapped into a new location (possibly to be refined later).
- **split →** content should be split across multiple new pages/sections.
- **rework →** needs significant rewriting to fit the new IA.
- **delete →** drop from the new docs (no longer relevant / superseded).

---

## 1. docs-old root

- `mission-capabilities/*` → **delete**
  - These describe specific mission bundles/capabilities (and things that aren't really offered anymore), not the UDS Core platform itself.

- `registry/*` → **delete** (for now?)
  - Registry/product-specific content is out of scope for UDS Core platform docs.

- `structure/*` → **split / rework**
  - `structure/bundles.md` → **split**
    - Concepts: `concepts/configuration-and-packaging/overview.md`, `concepts/configuration-and-packaging/bundles.md`.
    - Reference: `reference/operator-and-crds/package.md`, `reference/bundles` (if we decide to keep it) and How-to packaging docs.
  - `structure/packages.md` → **split**
    - Concepts: `concepts/configuration-and-packaging/overview.md`.
    - Reference: `reference/operator-and-crds/package.md` (schema/fields).
  - Other `structure/*` pages (if any beyond the two above) → likely **delete** or **rework** into packaging docs outside this repo.

- `tactical-edge-deployments/*` → **delete** (for now?)
  - Edge is out of scope for the core platform docs.

## Next steps for migration

- As pages are actually moved/rewritten per this plan, **add redirects** in `astro.config.mjs` so old URLs under
  `src/content/docs-old` keep working where it matters. Use the old → new mappings in the sections above to drive
  those redirects.
- The `scripts/integration-script.sh` helper currently focuses on copying reference-style docs into a few
  destinations. It will need to be updated to match this IA (for example, copying CLI, identity, or networking docs
  into `how-to-guides/`, `concepts/`, and `operations/` instead of only `reference/`).
